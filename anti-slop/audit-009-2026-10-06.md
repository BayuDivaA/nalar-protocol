# Landing-page Address Explainer controls

Mode: AFTER, following the user's existing preference. Scope: the network selector and address/transaction-hash input on `/`, not the full landing page, `/address` workspace or browser extension. Impeccable guided the visual refinement, Ponytail kept native controls and the existing form, and Antislop supplied this final audit. Design Read declared before implementation: technical minimalism, ENERGY 1 / RHYTHM 2 / MOTION 1.

## Findings

No actionable findings in the changed controls. Application code was not changed during this audit. This is not a whole-product accessibility, browser-compatibility or blockchain-security audit.

## Implementation

- Only `frontend/src/app/address/address.css` changed in the application. All new selectors are scoped to the landing-page entry form. The separate workspace's styles, existing component markup, validation, GET parameters, API client, backend, MCP and extension were preserved.
- The form uses one bounded surface, compact labels and existing neutral/cyan tokens. Inputs and network options have 44 px interaction heights. Existing responsive breakpoints and copy remain unchanged.
- Supported browsers get a themed native select picker with a selected-item checkmark, keyboard-focus indicator and short opening transition. The dropdown still uses the browser's selection, keyboard, Escape and outside-click handling. No dependency, React state or replacement form implementation was added.
- Native inner outlines no longer stack with the form boundary. Focus instead highlights the relevant field and uses a 2 px inset accent indicator for keyboard/text-input focus. Focus on unrelated controls was not suppressed.
- Motion only describes menu opening/closing and the chevron's open state; the existing reduced-motion preference disables these transitions.
- Native picker customization is progressively enhanced with `@supports`. Browser support reference: [MDN customizable select documentation](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/Customizable_select). Browsers without this feature retain the native menu; that fallback was source-reviewed, not run in a second browser engine.

### Recorded click-through

- Network selector: mouse opens the themed menu; ArrowDown opens it, another ArrowDown selects Testnet, Enter confirms; Escape and clicking the heading outside the menu dismiss it.
- Address input: Tab reaches it from the selector; its parent has the visible inset focus marker. Long 66-character hashes stay inside the input.
- Explain data, empty input: native required validation prevents navigation.
- Explain data, invalid `0x123`: native pattern validation prevents navigation.
- Explain data, Mainnet address: navigates to `/address?chainId=56&query=<the entered address>`.
- Explain data, Testnet hash: navigates to `/address?chainId=97&query=<the entered hash>`.
- Unavailable analysis: a temporary browser-only HTTP 503 substitute triggers the existing "Could not read on-chain data" feedback. It is not production mock data and does not generate an explanation or security result.
- Open the explainer: navigates to `/address`.
- Existing header theme button: clicking toggles light/dark and persists `nalar-theme`; both form themes retain their layout.
- Reduced motion: the opened picker's computed transition duration is `0s`.
